## 3. Shell、Dashboard 与核心页面信息架构

- **Shell**：工作台、职位管理、候选人管理、面试管理四个业务导航；左侧可展开，右上角为实际 HR 身份，全局多标签保留并简化；不得将候选人姓名当登录账号。
- **Dashboard**：指标 → 四个主待办 + 两个次级待办 → 待处理事项 → 今日面试 → 辅助统计。完整保持冻结 PRD 所需六类工作状态：待筛选、待安排、预约到时待确认、待面评、待决策、Offer 待处理。**指标按申请、职位、面试等各自单位计算**，不能混作人数。
- **候选人详情**：任务主区 + 资料侧栏 + 真实业务历史；四阶段显示当前招聘位置，详情可执行 HR 明确决策、面试/面评/Offer 等合法操作。
- **职位管理**：稳定 position_id、职位开放/关闭、查看关联申请；职位关闭不自动结束申请，有历史关联的职位不得直接清除。
- **申请列表**：一条 CandidateRecord 是一条职位申请，同名申请不同职位分别显示；招聘阶段、申请是否关闭、结束结果、当前任务、Offer 子状态分离。
- **面试管理**：scheduled/completed/cancelled 三态，预约到时需 HR 人工确认；不根据预约时间自动判定已完成。
- **面评**：一场面试仅有一份当前有效评价；推荐/不推荐/暂不确定必须有非空理由；专业评价人与登录 HR 分开。提交不自动晋级；已提交评价更正须原因、原新快照与实际操作者时间。
- **Offer**：preparing → sent → accepted 后由 HR 单独确认录用；sent → declined 时拒绝与关闭原子发生；接受≠已录用。拒绝、企业淘汰、候选人退出按冻结 PRD 的合法结束规则表达。

## 5. 交互与异常规则（设计基线）

### 5.1 正常状态与请求反馈

- 加载中保留列表、表头、筛选上下文，骨架行替代数据；未完成读取时不开放旧记录按钮。
- 筛选后 0 条显示“没有匹配的申请”与“清除筛选”；无任何记录的真实空态则提供“添加候选人”，两者不混淆。
- 加载失败显示“暂时无法查看申请记录”及“重新加载”；**不得将失败显示为 0 条**，避免错误工作判断。
- 写入时禁用重复点击；只有后端确认才显示完成。失败保留表单草稿与原业务真值，后端仍须保证幂等与事务性。
- 并发冲突显示“这条申请已有新进展”，先刷新最新状态后再操作，不能从陈旧状态直接继续提交。

### 5.2 招聘规则映射

- 仅能四阶段向前，正常不得跳阶段或回退；面试完成/评价提交不自动晋级。
- 当前有未完成的 scheduled 面试时先确认完成或取消；预约到时不等于已完成。
- 缺有效面评仍推进需 HR 填非空理由，保留缺评场次与历史事件；既有已豁免旧轮缺评不计入当前阶段待面评。
- 申请关闭后不允许安排面试、普通晋级或首次补录缺失面评；**已存在已提交评价**允许有痕更正。
- 旧数据未核实的阶段、时间、原因、Offer 事实显示“旧版待核实”或“未知”，不依据现有阶段生成假事件。

### 5.3 全局标签与响应式

| 容器宽度 | 侧栏 | 标签可见规则 | 内容策略 |
|---|---|---|---|
| ≥1280px | 默认 230px 展开，可手动收缩至 72px | 最多 5 个直接可见 | 详情任务主区+辅助侧栏 |
| 960–1279px | 默认 72px 图标栏，允许展开 | 最多 3 个直接可见 | 侧栏可下沉，主区自适应 |
| <960px | 默认隐藏；菜单按钮打开 240px 抽屉 | 当前页签 +“更多页面” | 表格在自身容器滚动，不强制页面整体横滚 |

标签宽度建议 120–220px，标题过长省略并在悬停/聚焦时显示全名；相同 route+申请 ID 复用标签，不同申请分别保留。超过上限统一收到“更多页面”，选择时当前标签可见。关闭活动标签返回最近访问仍打开的标签，或工作台；未保存表单须确认。跨刷新恢复待技术评估。
