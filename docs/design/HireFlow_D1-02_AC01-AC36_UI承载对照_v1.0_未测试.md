## 设计承载判定

- **有 UI 承载**：主要行为有对应页面、按钮、提示、表单或状态展示思路；仍可能需要 Codex 按规范落地。
- **仅部分 UI 承载**：迁移、鉴权、事务、并发、合法状态矩阵及数据精确计数不能通过静态 Figma 表明实现。
- **未进行软件验收**：没有运行 AC、没有修改源码、没有操作测试库或生产环境。后续由对话 A 组织 E2-01 技术评审，确定 API / DB 与事件模型后再将 AC 变成可执行测试。

## 设计与 PRD 自查风险

1. **数据统计单位**：申请总数、活跃申请、按面试计数的待面评、按申请计数的待办必须有不同聚合口径；不能图上好看就算验收。
2. **界面示例状态不能写成真实事实**：真实业务事件来自服务端；已有历史不依据当前阶段逆向补造。
3. **禁用按钮不是 API 安全保障**：直接 HTTP 请求仍须校验 R1 合法矩阵及 RBAC/认证。
4. **第三批含状态板、行为说明与申请列表完整 Shell 三态**：如需完整点击式 Figma prototype，需在 Owner 视觉审查通过后再排具体热区/导航连线；当前不声称已完成 Prototype 操作验收。
5. **Owner 已原则认可**：第三批 11/13/15/16 修订后可提交 A；不等于对话 A 已接受设计基线。
