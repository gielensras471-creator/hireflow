# V4 运行与维护

## 模式

| 模式 | 构建和入口 | 数据边界 |
| --- | --- | --- |
| 本地 V3 业务开发 | `pnpm dev:v3` | 回环开发环境 |
| 隔离 Demo | `pnpm run build:demo`、`pnpm run start:demo` | 虚构数据，SQLite 内存实例，独立签名密钥，默认端口 3302 |
| 正式 | `pnpm run build:v3`、`pnpm run start:v3` | 既有受控 SQLite，正式客户端来源及密钥 |
| 普通兼容 | `pnpm build` | 保留兼容入口，勿用它替代 V3 正式或 Demo 构建 |

Node.js 至少 24.15.0。本轮为 Node 24.17.0 与 pnpm 9.15.9。安装使用 `pnpm install --frozen-lockfile`，运行环境另核对安装的实际版本。正式入口要求 `NODE_ENV=production`，校验 `V3_PORT`、`V3_DATA_ROOT`、`V3_DATABASE_PATH`、`V3_JWT_SECRET` 和客户端来源，选择性使用 `V3_STATIC_DIR`。静态目录不得包含数据库。环境变量名和模板见 `server/config-v3.js` 与 `deploy/v3/v3.env.example`。生产配置和密钥应由服务管理器注入，并限制访问。Nginx 可提供 TLS、静态资源和 API 反代，部署时单独检查转发信任、真实入口、SPA 回退与跨域规则。仓库样例是配置参考。

Demo 每次进程初始化时按当前北京时间生成数据，停机数日再启动也按当时日期。重启丢弃内存库及旧认证令牌，允许同身份浏览器偏好继续保留。历史部署设计使用 systemd 每日北京时间 04:00 重启，期间可能短暂不可用。线上定时器与服务配置须经独立预检。公开入口当前是此前发布入口。

## 排查

- 登录失效先核对运行模式、账号与 JWT 更新策略。正式启动拒绝旧认证 schema 时核对 `server/scripts/database-v3.js` 的授权离线迁移流程。
- API 故障检查 `GET /api/v3/health`、实际服务端口、服务日志、来源配置及 HTTPS 反代。避免公开内网地址和令牌。
- 静态资源故障检查构建模式、Vite 公共 API 变量和 SPA 回退。数据库故障先检查隔离路径、权限、版本指纹与备份，勿用旧重置命令恢复正式环境。
- Demo 未重置时检查定时器、服务时区、重启日志及新旧身份。使用隔离环境验证生成数据和旧会话失效，线上操作留待批准。

## 公开 Demo 域名

公开演示使用 https://hireflowdemo.pixelweave.xyz/，由 Nginx 转发到独立回环 3302，API 保持同源 /api/v3。旧 https://demo.pixelweave.xyz/ 保留 HTTPS 并用 301 转发至新域名，保留路径与查询参数，HTTP 证书验证路径保留给续期。

浏览器会话与偏好按来源隔离。旧域名的数据不会通过重定向迁移，新域名首次使用时需要重新登录并按需选择偏好。每日北京时间 04:00 重置仍只重启 Demo 服务。

正式前端为 https://hireflow.pixelweave.xyz/，浏览器访问 https://api.pixelweave.xyz/api/v3。正式 API 保持回环 3301。不同来源的正式前端须在 API 的 CORS 白名单中配置精确 HTTPS 来源。
